# SuetaVPN — статический MVP

Интерактивный frontend-прототип лендинга и личного кабинета SuetaVPN. Он работает без backend: все пользовательские действия изменяют только локальное демо-состояние в браузере.

## Локальный запуск

Из этой директории запустите статический сервер:

```powershell
py -m http.server 4173
```

Затем откройте `http://localhost:4173/`. Прямое открытие `index.html` через `file://` не рекомендуется: часть browser API может быть недоступна.

Проверки модели и синтаксиса:

```powershell
node --check app.js
node --check mvp-core.js
node --test tests/mvp-core.test.cjs
```

## Что можно проверить

- responsive-лендинг, тёмную и светлую темы;
- демо-вход и восемь hash-маршрутов кабинета;
- выбор тарифа, расчёт периода, успешную покупку и недостаточный баланс;
- пополнение в диапазоне `100–50000 ₽` и одноразовый промокод `SUETA10`;
- локальные транзакции, реферальные copy/share, тикеты и ответы;
- привязку email, уведомления, выход и полный сброс демо-данных;
- модальные окна подключения, безопасный текстовый demo-config и пятишаговое обучение;
- клавиатурную навигацию, focus trap, Escape, ARIA tabs и reduced motion.

Маршруты кабинета:

- `#/dashboard`
- `#/subscriptions`
- `#/purchase`
- `#/balance`
- `#/referral`
- `#/support`
- `#/info`
- `#/profile`

## Демо-данные и ограничения

Состояние хранится в `localStorage` под ключом `suetavpn_mvp_v1`. Платежи, подписки, обращения, email, уведомления и VPN-подключение не отправляются во внешние сервисы. Скачиваемый файл прямо помечен как демонстрационный и не является VPN-конфигурацией.

Точка будущей интеграции — чистые операции в `mvp-core.js`, возвращающие результат вида `{ ok, state, message, code? }`. При подключении backend их можно заменить API-адаптером, сохранив маршруты и UI-сценарии. До серверной интеграции нельзя использовать этот MVP для реальных оплат, авторизации или выдачи VPN-доступа.
