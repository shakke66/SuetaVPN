# SuetaVPN: React-MVP и production-ready дизайн кабинета

Дата: 13 августа 2026 года
Статус: дизайн утверждён пользователем в чате

## 1. Цель

Перенести существующий статический MVP SuetaVPN на React + Vite + TypeScript и одновременно привести интерфейс к утверждённому виду на основе референсов Gaz Network. Получившийся frontend должен быть пригоден для показа Тимуру и стать постоянной основой будущего production-кабинета: при подключении backend дизайн, маршруты и компоненты не меняются, а локальные адаптеры заменяются сетевыми реализациями.

Сайт остаётся полностью рабочим без backend: авторизация, баланс, покупка подписки, рефералы, тикеты, уведомления, RU/EN, темы и onboarding выполняются локально и сохраняются в браузере. Во всех пользовательских текстах удаляются `DEMO`, «демо», «демонстрационный» и похожие пометки.

## 2. Границы этапа

В этап входят:

- публичный лендинг;
- отдельная авторизация;
- личный кабинет со стабильной оболочкой;
- локальная бизнес-логика и версионированное хранилище;
- две темы и полная локализация RU/EN;
- плавные переходы и адаптивная вёрстка;
- тесты, desktop/mobile Browser QA и production-сборка;
- публикация содержимого `сайт` в отдельном приватном репозитории GitHub и проверка GitHub Pages;
- отправка проверенной Pages-ссылки пользователю через ранее указанный Telegram-бот.

До отдельного backend-этапа не входят:

- серверная проверка Telegram `initData`;
- реальная отправка email и кодов;
- банковский эквайринг и реальные списания;
- чтение тарифов, подписок и баланса из PostgreSQL;
- реальные ответы операторов поддержки, WebSocket и push;
- выпуск VPN-ключей и production-конфигураций.

Frontend не выполняет запросов к production API и не хранит секреты. При публикации репозиторий нельзя делать публичным без отдельного разрешения пользователя.

## 3. Технологическая архитектура

### 3.1. Стек

- React;
- Vite;
- TypeScript в строгом режиме;
- React Router с `HashRouter`, совместимым с GitHub Pages;
- React Context + `useReducer` для локального состояния;
- Vitest + React Testing Library для unit- и component-тестов;
- CSS Modules либо тематически разделённые обычные CSS-файлы на базе общих design tokens;
- без UI-kit, CSS-framework и отдельной animation-библиотеки.

Зависимости добавляются только там, где они нужны архитектуре или проверкам. Денежная логика остаётся чистой TypeScript-логикой без зависимости от React.

### 3.2. Слои

Приложение разделяется на четыре уровня:

1. `domain` — типы, тарифный каталог, миграции, расчёты и чистые атомарные операции.
2. `adapters` — контракты `auth`, `billing`, `subscriptions` и `tickets`. На этом этапе они работают с локальным состоянием; позже те же интерфейсы получат API-реализации.
3. `app` — router, providers, route guards, transition coordinator, темы и локализация.
4. `pages/components` — экраны и переиспользуемые UI-компоненты без прямого доступа к `localStorage`.

### 3.3. Стабильная оболочка

`AppShell` монтируется один раз для всех защищённых маршрутов и содержит desktop-header, mobile-header, drawer, нижнюю навигацию, route viewport, notification popover, modal/toast/live-region roots. При переходе меняется только содержимое route viewport. Это устраняет нынешнюю полную замену `app.innerHTML`, из-за которой header и нижняя панель выглядят как перезагруженные.

События приложения вызывают методы адаптеров и dispatch доменных действий. UI не изменяет баланс, подписку или тикеты напрямую.

## 4. Маршруты и доступ

Маршруты:

- `#/` — публичный лендинг;
- `#/auth` — авторизация;
- `#/dashboard` — главная кабинета;
- `#/subscriptions` — текущая подписка;
- `#/purchase` — отдельная страница покупки;
- `#/balance` — баланс и пополнение;
- `#/referral` — реферальная программа;
- `#/support` — тикеты;
- `#/info` — FAQ и документы;
- `#/profile` — профиль.

Старый `#/welcome` перенаправляется на `#/`. Неизвестный маршрут перенаправляется на `#/dashboard` при активной сессии и на `#/` без неё.

Все маршруты кабинета защищены. Неавторизованный переход сохраняет желаемый маршрут и открывает `#/auth`; после успешного входа пользователь возвращается туда. В обычном браузере выход очищает только сессию и ведёт на лендинг, сохраняя остальные локальные данные. В Telegram Mini App пользователь входит автоматически, а выход в интерфейсе отсутствует.

## 5. Локальное состояние и миграция

Новая схема хранится под версионированным ключом и содержит:

- preferences: `theme`, `locale`, `onboardingCompleted`;
- auth session и профиль;
- wallet balance и транзакции;
- активную подписку и черновик покупки;
- реферальную статистику и Telegram-ссылку;
- тикеты, сообщения и тикетные уведомления.

Тарифный каталог является конфигурацией приложения и не дублируется внутри пользовательского состояния. Все даты сохраняются в ISO 8601, а отображаются через текущую locale.

Миграция со старого `suetavpn_mvp_v1`:

- сохраняет корректные тему, баланс, транзакции, профиль, тикеты, реферальные показатели и onboarding;
- преобразует старый session flag в новую локальную сессию;
- удаляет СТАРТ и СЕМЬЮ из каталога и выбора;
- заменяет неизвестный или удалённый активный тариф на БАЗУ;
- приводит лимиты активной подписки к параметрам нового каталога;
- оставляет только Telegram-реферальную ссылку;
- заменяет общие notification settings моделью тикетных событий;
- при повреждённом JSON или неправильных типах восстанавливает безопасные значения по умолчанию.

Миграция выполняется один раз, не выбрасывает исключения наружу и покрывается тестами.

## 6. Тарифный каталог

Frontend использует последнюю зафиксированную production-конфигурацию репозитория. Источник истины production-системы — PostgreSQL `subscription_categories` и `config_prices`; после подключения backend статический каталог заменяется ответом API.

### БАЗА

- 1 месяц — `250 ₽`;
- 3 месяца — `490 ₽`;
- 6 месяцев — `940 ₽`;
- 12 месяцев — `1 390 ₽`;
- до 1 Гбит/с;
- 4 локации;
- до 4 устройств;
- Android TV и Apple TV;
- безлимитный трафик.

### ЭЛИТА

- 1 месяц — `310 ₽`;
- 3 месяца — `690 ₽`;
- 6 месяцев — `1 290 ₽`;
- 12 месяцев — `1 990 ₽`;
- до 10 Гбит/с;
- 6 локаций;
- до 6 устройств;
- Android TV и Apple TV;
- обычные серверы без ограничений;
- обход глушилок — 40 ГБ в месяц.

Итоговая стоимость берётся из точной таблицы периода, а не рассчитывается по старым скидкам `5/10/20%`. Если интерфейс показывает выгоду, она вычисляется справочно относительно помесячной цены. Названия конкретных локаций не выдумываются: в repository source закреплено только их количество.

## 7. Авторизация

Лендинг публичный. «Личный кабинет», «Подключиться» и CTA тарифа ведут на `#/auth`; выбранный тариф сохраняется в черновике покупки.

Экран авторизации повторяет структуру референса Gaz Network и поддерживает:

- вход через Telegram;
- вход по email;
- регистрацию по email;
- подтверждение шестизначным кодом.

В обычном браузере Telegram-кнопка проходит короткое локальное pending-состояние и создаёт локальную сессию. Email-flow валидирует поля, создаёт одноразовый шестизначный код внутри браузера и показывает его пользователю как код локальной проверки; введённый код сверяется с активным challenge и имеет ограниченное время жизни. Интерфейс не заявляет, что письмо действительно отправлено.

В Telegram Mini App наличие `window.Telegram.WebApp.initDataUnsafe.user` создаёт локальную Telegram-сессию автоматически. Эти данные используются только для MVP-интерфейса и не считаются серверно проверенной личностью. Будущий backend обязан валидировать подписанную строку `initData`.

## 8. Экраны кабинета

### 8.1. Навигация и header

Desktop-header содержит логотип, основную навигацию, тему, колокольчик тикетов, RU/EN, аватар профиля и выход. На промежуточной ширине подписи навигации могут скрываться, но остаются доступные названия и tooltips.

На ширине менее `1024 px` используются компактный mobile-header, drawer и нижняя панель. Нижняя панель всегда имеет порядок:

1. Главная;
2. Подписки;
3. Баланс;
4. Рефералы;
5. Поддержка.

Drawer содержит профиль пользователя, полный список разделов, переключатели темы и языка и выход в обычном браузере. В Telegram Mini App пункт выхода не рендерится.

### 8.2. Главная

Главная показывает приветствие, активную подписку, срок, доступные устройства и кнопку подключения. Для БАЗЫ вместо фиктивного лимита трафика отображается «Безлимитный трафик». Для ЭЛИТЫ отдельно показываются безлимитные обычные серверы и месячный лимит обхода глушилок 40 ГБ.

Баланс и рефералы представлены двумя широкими равновысокими карточками. Внутри карточки контент расположен горизонтально: иконка и подпись слева, ключевое значение и действие справа. На телефоне карточки складываются друг под другом, но сохраняют горизонтальную внутреннюю композицию. Быстрые действия остаются отдельным компактным рядом/списком.

### 8.3. Подписки

Экран содержит только текущую подписку, её статус, срок, параметры и явные кнопки «Продлить», «Сменить тариф» или «Купить подписку» в зависимости от состояния. Блок «Доступные тарифы» полностью удаляется. Все действия ведут на `#/purchase`.

### 8.4. Покупка

Покупка остаётся отдельной страницей. На desktop слева находятся два последовательных блока: выбор БАЗЫ/ЭЛИТЫ и выбор периода. Справа находится итог заказа. Правая карточка растягивается ровно до общей высоты левой колонки и совпадает с ней по верхней и нижней границе; внутренний CTA прижимается к нижней части карточки без пустого провала.

На ширине менее `768 px` две карточки тарифов идут одной колонкой, периоды — сеткой 2×2, итог становится отдельным нижним блоком. На ширине `768–1023 px` тарифы остаются двухколоночными, а итог переносится под выбор. Карточки не ужимаются до нечитаемого состояния.

Выбор тарифа и периода мгновенно обновляет итог. Покупка атомарно списывает точную сумму с локального баланса, создаёт транзакцию и обновляет подписку. Продление того же тарифа добавляет срок к текущей дате окончания, если подписка ещё активна. Смена тарифа активирует выбранный тариф сразу и отсчитывает новый срок от момента покупки. При нехватке средств черновик сохраняется, пользователь видит недостающую сумму и может перейти на `#/balance`.

### 8.5. Баланс

Все блоки идут одной вертикальной последовательностью без пустых зон:

1. текущий баланс;
2. промокод;
3. пополнение;
4. история операций.

Форма пополнения содержит сумму `100–50 000 ₽`, синхронизированные number/range controls, выбор СБП или банковской карты и кнопку подтверждения. Реквизиты карты не запрашиваются. После локального pending-состояния баланс и история обновляются атомарно. Повторное подтверждение во время операции блокируется.

История изначально свёрнута и открывается стрелкой. Пустая история имеет отдельное компактное состояние. Существующий локальный промокод `SUETA10` один раз начисляет `100 ₽`; тексты не называют его демонстрационным.

### 8.6. Рефералы

Остаются показатели процента, приглашённых, активных и заработанного, условия программы и только Telegram-ссылка. Доступны копирование и системный share с fallback на копирование. Ссылка кабинета и блок «Последние приглашённые» удаляются.

### 8.7. Поддержка и уведомления

Поддержка содержит список тикетов, выбранный диалог, создание обращения и ответ. Локально сохраняются тема, сообщения, имя вложения, время и статус. Пустые поля отклоняются рядом с соответствующим полем.

Колокольчик является центром только тикетных событий:

- обращение создано;
- ответ поддержки;
- статус изменён.

Событие содержит `ticketId`, тип, текст, время и `readAt`. Непрочитанные показывают badge на колокольчике. Панель имеет заголовок «Уведомления о тикетах», список либо пустое состояние как в референсе и действие «Прочитать все» при наличии непрочитанных. Клик помечает событие прочитанным и открывает нужный тикет на `#/support`. Desktop-popover привязан к колокольчику; на телефоне занимает почти всю доступную ширину под header. Outside click и `Escape` закрывают панель и возвращают фокус.

### 8.8. Информация

Остаются три вкладки:

- FAQ;
- Соглашение;
- Конфиденциальность.

Правила, Оферта и Статусы удаляются. FAQ использует равные по ширине и минимальной высоте заголовки; можно раскрыть несколько ответов одновременно. На лендинге первый ответ открыт по умолчанию, в кабинете все ответы закрыты. В Соглашении и Конфиденциальности отображаются аккуратные production-style placeholders о будущем размещении документов, без ложных юридических текстов.

### 8.9. Профиль

Профиль показывает аватар, имя, username, email и дату регистрации. Здесь нет блоков выбора темы, сброса локальных данных, повторного запуска onboarding или управления входом/выходом. Тема, язык и выход доступны только в header/drawer.

## 9. Локализация

RU и EN охватывают лендинг, авторизацию, все страницы кабинета, формы, validation errors, toast, статусы, уведомления, onboarding и accessibility labels. В компонентах нет захардкоженных пользовательских строк.

Язык сохраняется в preferences, применяется без перезагрузки и обновляет `document.documentElement.lang`. Даты и суммы форматируются через `Intl` для активной locale. Пользовательские значения, username и сообщения тикетов не переводятся.

## 10. Визуальная система

### 10.1. Темы

Светлая тема сохраняет удачную текущую палитру:

- background `#F5F6F8`;
- surface `#FFFFFF`;
- secondary surface `#FAFAFB`;
- text `#191A1D`;
- muted `#6E7178`;
- border `#E2E4E8`.

Тёмная тема становится глубже и ближе к Gaz Network:

- основной фон около `#101111`;
- основные поверхности `#242525–#292A2A`;
- вложенные поля около `#1B1C1C`;
- спокойные границы `#3A3B3B–#454646`;
- основной текст почти белый;
- вторичный текст остаётся контрастным и не превращается в серую дымку.

Design tokens являются единственным источником цветов, радиусов, теней, spacing и motion. Основной радиус карточек `16–18 px`, интерактивная высота не менее `44 px`.

### 10.2. Фон и бренд

Фон полностью статичный: допускаются только неподвижные цвет и малоконтрастные radial gradients. Запрещены Canvas, частицы, падающие/движущиеся линии, `requestAnimationFrame` и бесконечные декоративные keyframes.

## 11. Анимации

`RouteTransition` знает порядок пяти основных мобильных вкладок. При переходе к пункту с большим индексом новый экран входит справа, старый уходит влево; при возврате направление меняется. Оба route-layer существуют одновременно до окончания `260 ms`, после чего исходящий удаляется. `AppShell`, header, drawer и bottom navigation не размонтируются.

Переходы к покупке, информации, профилю и конкретному тикету используют спокойный короткий fade/translate. На desktop амплитуда меньше, чем на mobile. Активный индикатор нижней панели перемещается между пунктами, а сама панель остаётся неподвижной.

Accordion реализует анимацию фактической высоты либо CSS grid `0fr → 1fr` вместе с opacity и поворотом chevron за `220–280 ms`; контент не переключается мгновенно через `hidden` до завершения закрытия. Drawer, notification popover, modal и toast используют единый мягкий easing.

Onboarding-overlay монтируется один раз. Перед первым показом он остаётся невидимым, измеряет целевой элемент и tooltip, выставляет координаты и только затем появляется. Переход между шагами меняет содержимое и геометрию существующего overlay, поэтому элемент не вспыхивает в точке `(0, 0)`. Положение отслеживается через `ResizeObserver`, resize и scroll.

При `prefers-reduced-motion: reduce` route, accordion, drawer, popover и onboarding сразу принимают конечное состояние без движения; функциональность и фокус сохраняются.

## 12. Адаптивность

- `1440 px` — полная desktop-композиция и свободные отступы;
- `1024 px` — компактный desktop/tablet-header без переполнения;
- `768 px` — mobile shell с drawer и нижней навигацией;
- `390 px` и `360 px` — одно- или двухколоночные мобильные компоненты без горизонтального переполнения страницы.

Нижняя навигация учитывает safe-area. Контент не скрывается под ней. Таблицы превращаются в карточки/строки, а не сжимаются. Purchase, top-up и ticket layout складываются последовательно. Touch targets имеют размер не менее `44×44 px`.

## 13. Ошибки, атомарность и доступность

- Domain operations возвращают типизированный результат `ok`, `code`, `messageKey` и данные результата.
- Validation errors показываются у полей и анонсируются через `aria-live`.
- Покупка и пополнение обновляют связанные данные одной reducer-операцией; частично применённого состояния быть не может.
- Submit блокируется на время pending-состояния.
- Ошибка сохранения в `localStorage` не разрушает текущую сессию и показывается понятным toast.
- Modal, drawer и popover имеют focus trap, закрытие по `Escape`, outside click там, где это безопасно, и возврат фокуса инициатору.
- Tabs, accordions и навигация поддерживают клавиатуру и корректные `aria`-состояния.
- Контраст текста и focus ring проверяется в обеих темах.
- Telegram haptic feedback является необязательным enhancement и никогда не блокирует действие.

## 14. Проверка готовности

### Автоматические проверки

- unit-тесты миграции старого состояния, восстановления повреждённого JSON и tariff fallback;
- точные цены всех восьми сочетаний тарифа/периода;
- успешная и отклонённая покупка, продление и смена тарифа;
- границы пополнения и атомарное создание транзакций;
- создание/ответ/статусы тикетов и read/unread уведомления;
- route guards и Telegram auto-auth;
- RU/EN и переключение locale;
- component-тесты auth, FAQ, истории, theme/language controls, notification panel и нижней навигации;
- TypeScript check и production build.

### Browser QA

На `360`, `390`, `768`, `1024` и `1440 px` проверяются:

- лендинг и переход через `#/auth`;
- Telegram- и Email-flow;
- persistent shell и направленные переходы нижней панели;
- обе темы и RU/EN;
- onboarding без вспышки;
- пополнение, история, успешная покупка и нехватка средств;
- тикеты, колокольчик, read state и переход к обращению;
- drawer, modal, focus, `Escape` и keyboard-only navigation;
- `prefers-reduced-motion`;
- отсутствие horizontal overflow, console errors и битых assets.

### Публикация

Перед push выполняются production build, тесты и проверка индексируемого дерева на секреты, персональные файлы и старые абсолютные пути. Через `gh` подтверждается аккаунт `shakke66` и право создать приватный репозиторий. Публикуется только каталог сайта и необходимые workflow-файлы.

GitHub Pages считается готовым только после успешного открытия live URL и короткого повторного smoke QA. Если текущая авторизация GitHub не имеет права создать репозиторий либо тариф GitHub не поддерживает Pages для приватного репозитория, сайт не переводится в public автоматически: блокировка сообщается пользователю для отдельного решения. После успешной проверки URL отправляется пользователю через ранее указанный Telegram-бот без сохранения токена в файлах, логах или Git.
